# 需求池模块开发计划

> 基于 Calicat 需求卡片「需求池 - 需求列表 PRD」的功能检查结果，制定的修复与完善计划。
>
> 创建日期：2026-07-07

---

## 一、背景

根据 Calicat 设计文件（file_id: 2074038764039397376）中的「需求池 - 需求列表 PRD」需求卡片，对当前代码实现进行了全面功能检查，发现以下核心问题：

1. **API 返回数据格式不统一**：`/api/meta` 返回 `{ code, data: { users, iterations, ... } }`，但部分页面直接访问 `meta?.users` 而非 `meta?.data?.users`，导致下拉框为空
2. **枚举值不匹配**：数据库用 `p0/p1/p2/p3`，前端用 `high/medium/low`；数据库用 `in_progress/pending`，前端用 `developing/reviewing`
3. **详情页数据格式不匹配**：API 返回 `{ code, data }` 包装格式，页面直接访问字段导致内容为空
4. **核心功能未实现**：详情页编辑按钮只有 `console.log`，Bug 提交不调用 API
5. **其他页面受波及**：任务看板页报错 `Cannot read properties of undefined (reading 'slice')`

整体完成度约 **50%**。

### 执行策略

> **注意**：以下执行顺序已经过 grill-with-docs session 修订，新增了第 0 步（Auth 系统）和第 5 步（数据库联调）。

1. **先修阶段一 + 阶段二**（约 4h）—— 解决所有页面的数据格式和枚举问题，这一步完成后大部分页面就能正常显示数据

3. **然后修阶段三**（约 3h）—— 补全详情页的编辑和 Bug 提交
   - 详见 ADR-0007
4. **处理阶段五、六**（约 6h）—— 修复其他页面并做功能增强
5. **对接数据库接口联调**（约 2h）—— 端到端验证所有 API 与 MySQL 数据库的实际交互

## 五、关键 Bug 清单

### Bug 1: Meta API 数据格式不匹配（影响多个页面）

**问题**：`/api/meta` 返回 `{ code: 200, data: { users, iterations, ... } }`，但 `requirements.vue`、`tasks.vue`、`bugs.vue` 等页面直接访问 `meta?.users` 而非 `meta?.data?.users`，导致数据为 undefined。

**影响**：
- 新建需求弹窗的模块/负责人/迭代下拉框为空
- 任务看板页面报错 `Cannot read properties of undefined (reading 'slice')`
- 迭代筛选下拉为空

**对比**：`index.vue`（仪表盘）正确使用 `meta?.data?.users`，所以仪表盘正常。

### Bug 2: 优先级/状态枚举值不匹配

**问题**：
- 数据库 `priority`：`p0/p1/p2/p3`
- 前端 `Priority` 类型：`high/medium/low`
- 数据库 `status`：`draft/pending/approved/rejected/in_progress/completed/closed`
- 前端 `Status` 类型：`draft/reviewing/approved/developing/completed`

**影响**：列表中大部分需求的优先级和状态标签显示为空。

### Bug 3: 需求详情页数据格式不匹配

**问题**：`/api/requirements/[id]` 返回 `{ code: 200, data: { ... } }`，但页面使用 `useFetch<Requirement>` 直接访问 `requirement.title` 等字段，实际应该访问 `requirement.data.title`。

### Bug 4: 详情页编辑功能未实现

**问题**：`editRequirement()` 函数只有 `console.log('Edit requirement:', requirement.value)`，标注 TODO。

### Bug 5: 详情页 Bug 提交不调用 API

**问题**：`onBugSubmit()` 函数只有 `console.log('Bug submitted:', bugData)`，不调用 `POST /api/bugs`。
